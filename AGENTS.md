# Работа над «Поставкой»

Перед началом работы прочитайте `PROJECT_STATE.md`, `TASKS.md`, `ROADMAP.md`, `docs/architecture/README.md` и соответствующий раздел `README.md`. Эти файлы должны позволять продолжить работу с другого устройства без доступа к прежнему чату. Сверяйте записанное состояние с фактическим Git, открытым PR, CI и стендом; при расхождении исправляйте документацию.

## Продуктовые границы

«Поставка» — сервис поиска и сравнения поставщиков для закупщика. Текущая реализация — прототип и демо, не готовая коммерческая версия. Не выдавайте ручной каталог за живой интернет-поиск, детерминированный скоринг — за независимую проверку надёжности, а демонстрационный интерфейс AI — за подключённую LLM. Не обещайте совместимость с конкретной конфигурацией 1С без испытания. Не добавляйте загрузку файлов документов в демо: это отложено до MVP, см. `ROADMAP.md`.

Первоначальный план ограничен пятью итерациями, шестую не создавайте. Дальнейшие этапы до MVP и коммерческого выпуска — отдельный план развития, а не задним числом выполненные итерации. Изменение обязательных требований и публичная публикация репозитория требуют решения владельца.

## Работа с кодом и данными

Сохраняйте существующий frontend, историю Git и авторство коммитов; не делайте force push и не переписывайте опубликованную историю. Ведите работу через обозримый PR, записывайте фактически пройденные проверки и не сливайте PR без решения владельца. Проверяйте `pnpm typecheck`, `pnpm test`, `pnpm build` для затронутой функциональности. Не добавляйте в Git секреты, SQLite-базы, резервные копии, данные пользователей и журналы с чувствительными сведениями. Локальные настройки и пароль alwaysdata задаёт владелец вне репозитория.

Приложение развёрнуто на бесплатном alwaysdata; SQLite-файл расположен вне каталога кода. Перед обновлением стенда сохраняйте резервную копию БД и проверяйте, что архив не содержит БД или секретов. Учитывайте наблюдавшиеся задержки HTTP до 57 секунд и не показывайте пользователю ложные нули при ошибке API.

## Передача работы следующему агенту

После значимого изменения обновите `PROJECT_STATE.md` (что действительно работает, версия на стенде, открытые риски), `TASKS.md` (следующее проверяемое действие), `ROADMAP.md` при смене объёма и материалы защиты, если изменилось продуктовое обещание. Укажите PR и проверенный commit SHA, а не только локальную ветку. Новый агент начинает с чтения этих файлов, проверки фактического состояния и продолжения только разрешённого объёма. Не считайте отсутствие ошибки CI доказательством работы внешних AI/API или опубликованного стенда.
